# Synrad3D wall file 生成ツール

SuperKEKB のラティス（dispog）と Duct_Table の断面情報から、Bmad/Synrad3D の
`wall_file`（真空チェンバ断面の定義）を半自動生成するツール一式です。
AutoCAD 配置スクリプト生成など本体側の機能は
[`../README.md`](../README.md) を見てください。

```
synrad3d/
├── synrad3d_wall.py               wall file 本体の生成
├── dxf_to_wall.py                 CAD 断面 DXF → 形状ライブラリ
├── config/
│   ├── wall_shapes.json           断面コード → 断面形状（型番の諸元。重複なし）
│   ├── {her,ler}_wall_inserts.json  s を指定した断面の差し込み台帳（設置の一覧）
│   └── wall_profiles/*.csv        差し込みが読む開口プロファイル（QCSL / QCSR 等）
├── dxf/                           断面 DXF。ファイル名がそのまま断面コードになる
├── wall/                          生成した wall file（出力先）
└── reference/                     旧 wall file など参照用
```

このフォルダのスクリプトは `skekb_layout.py` を 1 つ上から読み込み、config も
「自分の隣 → 1 つ上」の順に探します。Duct_Table 側の `*_ducttype.json` は上の
`config/` に、wall 側の `wall_shapes.json` は `synrad3d/config/` に置いたまま、
どちらも参照できます。

---

## 1. 使い方

入力は次の 4 つです。

- 各要素の縦位置 **s** … dispog
- 各要素の **断面コード**（`f90x220_Ar`、`104x50`、`f80` など） … Duct_Type の Cross Section
- **形状ライブラリ** `config/wall_shapes.json` … 断面コードから自動生成できない形状の頂点
- **差し込み台帳** `config/{her,ler}_wall_inserts.json` … 断面コードでは決まらない、
  「この s にこの形状を置く」という情報（IR・コリメータなど）

```bash
# 出力ファイル名を省略すると <dispog名>_<ring>.wall
python synrad3d_wall.py sler_1802_60_1.dispog

# 出力先を指定（途中のフォルダが無ければ作ります）
python synrad3d_wall.py sler_1802_60_1.dispog -o wall/sler_1802_LER.wall3d

# dispog を読まず、形状ライブラリだけを頂点規則で検証する
python synrad3d_wall.py --check-shapes
```

> `-o` は **出力ファイル名**です（`dispog2scr.py` の `-o` は出力フォルダなので、
> 同じオプション名でも意味が違う点に注意）。

出力は Synrad3D の namelist 形式（`&place` で s に断面を配置、`&shape_def` で断面形状を
定義）。Synrad3D は隣接断面間を r(θ) で線形補間するので、同一断面が続く区間は両端だけ
置きます。実行すると、断面配置数・形状数・差し込みの適用結果・要定義の断面コード・
頂点規則に違反した形状が表示され、同じ内容がファイル冒頭にもコメントで入ります。

## 2. 断面コード → 形状 の対応

| 種別 | 例 | 扱い |
|------|----|------|
| レーストラック `WxH` | `104x50`, `60x40`, `122x50` | **自動**（半幅 W/2・半高 H/2、両端は半径 H/2 の半円） |
| 円 `fNNN` / `fNN_MM` / `fNN.M` | `f80`, `f150`, `f15_98`, `f9.6` | **自動**（直径 NNN.MM mm の円）|
| 円の枝番 `fNNN-n` | `f20-1`, `f20-2` | **自動**（同径パイプの枝番。テーパーではない） |
| テーパー `A^B` / `A-B` | `f90^f80`, `f90-f90x220_Ar` | A,B,… を要素の前後に分けて配置（区間で補間＝テーパー） |
| アンテチェンバ等 | `f90x220_Ar`, `f90x220_St`, `f80x220_Ar`, `f90x220H24`, `f50x190_Ar` | `config/wall_shapes.json` に定義（整備済み） |

**`WxH` は矩形ではなくレーストラック**です（両端が半円）。旧 wall file の該当形状
（104x50 / 122x50 / 76x48 / 65x48 / 60x40）はすべてこの規則と一致します。たとえば
`104x50` は `v(1)=(0.052, 0)`, `v(2)=(0.027, 0.025, 0.025)`, `v(3)=(0, 0.025)`。

円コードの小数点は `_` でも `.` でも書けます（旧ファイルでは `f15_98` と `f9.6` が
混在）。末尾の `-n` は同径パイプの枝番なので、テーパーの区切り記号 `-` とは区別して
います（`-` は前後の両方が断面コードとして解釈できるときだけ区切りとして扱います）。

## 3. `config/wall_shapes.json`（形状ライブラリ＝型番の諸元）

断面コードごとに `shape_def` を定義します。**1 つの断面コードにつき 1 エントリ**で、
s の情報は持ちません（s は 10.3 の差し込み台帳が持ちます）。旧 wall file から抽出した
アンテチェンバ系 7 種とコリメータ系 5 種が整備済みです。

```json
"f90x220_Ar": {
  "r0": [0.0, 0.0],
  "v": [
    [0.1100,  0.0000],
    [0.1100,  0.0028],
    [0.1058,  0.0070,  0.0042],
    [0.0565,  0.0070],
    [0.04168, 0.01697, -0.016],
    [0.0,     0.0450,   0.045],
    [-0.04168, 0.01697, 0.045],
    [-0.0565, 0.0070,  -0.016],
    [-0.0618, 0.0070],
    [-0.0660, 0.0028,   0.0042],
    [-0.0660, 0.0000]
  ]
}
```

- `r0`：r(θ) を張る中心［m］（省略時は原点）。描画の原点ではありません（→ 10.4）。
- `v`：頂点 `[x, y, (radius_x), (radius_y), (tilt)]`［m］。`radius_*` と `tilt` は
  **1 つ前の頂点からその頂点までの区間**に付く円弧の指定で、`radius_x > 0` で凸、
  `< 0` で凹、`radius_y` も与えると楕円弧。省略すると直線。
- 頂点 1 個＋`radius_x` は特別扱いで円（`radius_y` も与えれば楕円）になります。
  `"v": [[0.0, 0.0, 0.0105, 0.0135]]` で半幅 10.5 mm・半高 13.5 mm の楕円。

**頂点の制約（Bmad `wall3d_section_initializer`）**。書き出し前にツールが検証し、
違反があれば警告します。`--check-shapes` でライブラリ単体でも検査できます。

- θ = atan2(y, x) が**単調増加**であること。隣接頂点の θ 差は 0 より大きく 180° 未満。
- `radius_x = 0` で `radius_y ≠ 0` は不可。`radius_x` と `radius_y` は同符号。
- 総回転角は 2π 未満。
- つまり断面は r0 から見て**星形**（r(θ) が一価）でなければなりません。r が θ とともに
  減っても構いませんが、**内側へ張り出す形状は表現できません**。コリメータのブレードの
  ような形は近似が必要で、サブチェンバでも直りません（サブチェンバは和集合なので、
  開口を広げる方向にしか効きません）。

**対称性の自動展開**。全頂点が x ≥ 0 かつ y ≥ 0 なら両軸対称として 1/4 だけ、
y ≥ 0 のみなら x 軸対称として上半分だけ書けば、Bmad が全周に展開します
（`f90x220_St` は 1/4 記述、`f90x220_Ar` は上半分記述）。折り返し点の頂点は重複
コピーされず、鏡像側では `radius` / `tilt` が 1 つ隣の頂点へずれて `tilt` の符号が
反転します（頂点を手で書く分には意識不要）。

自動生成もライブラリにも無いコードは、寸法から**仮の外接矩形**を置き、実行時に
「要定義」と警告して、ファイル内にも `! ← PLACEHOLDER` と印を付けます。

## 4. `config/{her,ler}_wall_inserts.json`（差し込み台帳＝設置の一覧）

IR のテーパーやコリメータのように、**断面コードでは決まらず s で決まる**断面は
こちらに書きます。形状ライブラリ（型番の諸元、重複しない）と差し込み台帳
（設置の一覧、同じ形状が何か所にも現れる）を分けるのは、Duct_Type と Component を
分けているのと同じ多対一の関係だからです（→ 本体 README 第9章）。s はリング固有なので
リング別のファイルにしています。

**(a) 既定の形状を s に置く**

```json
{ "name": "D02V1", "shape": "D02V1", "s": [2997.000, 2997.010], "guard": 0.30 }
```

- `shape`：`wall_shapes.json` のコード、または自動生成できるコード（`f90` など）。
- `s`：単一値なら 1 点、`[s0, s1]` なら区間の両端に同じ断面を置く。
- `replace`（既定 true）：その s 範囲の自動生成断面を取り除いてから差し込む。
- `s_center` + `length`：**中心 s と先端部の長さ L** で書く形。`s` の代わりに使うと
  s = `s_center` ± L/2 に同じ断面を置きます。コリメータはこちらが書きやすいはずです。
- `guard`：区間の外側 `guard` [m] の位置に、もとの断面をもう一度置いて補間のにじみを
  止める。単位は **m**。**0 のままだと、隣の自動断面（何十 m 先ということもあります）
  まで一直線にテーパーした巨大な漏斗になります。**短いコリメータでは必ず指定して
  ください。値は前後のテーパー長、不明なら隣接ダクトの端までが目安です。
- `disabled`: true で、行を消さずに無効化できます。

たとえば `{"name": "D06H3", "shape": "D06H3", "s_center": 1788.02199, "length": 0.010,
"guard": 0.28740}` は次を出力します（旧 wall file と同じ形）。

```
&place section = 1787.72959, "D06H3_in",  "f90x220_Ar" /
&place section = 1788.01699, "D06H3_tip", "D06H3" /
&place section = 1788.02699, "D06H3_tip", "D06H3" /
&place section = 1788.31439, "D06H3_out", "f90x220_Ar" /
```

`&place` の 2 番目のラベルには、自動生成部では dispog の要素名が、差し込み部では
`name` に `_in` / `_tip` / `_out` を付けたものが入ります。

**(b) CSV のプロファイルを読み込む**

IR のように「s に対する開口寸法の表」がある場合は、CSV をそのまま読ませられます。

```json
{
  "name": "IR right (QCSR)",
  "profile": {
    "file": "wall_profiles/QCSR.csv",
    "s_column": 0, "width_column": 1, "height_column": 2,
    "s_scale": 0.001, "s_offset": 0.4985012834226,
    "s_origin": 3016.315, "s_direction": -1,
    "size_scale": 1.0
  },
  "replace": true
}
```

- CSV は `s, 水平全幅, 垂直全幅` の 3 列（列番号は指定可）。単位は `size_scale` で mm に
  換算します（既定 1.0 ＝ 生値が mm）。
- s は `s = s_origin + s_direction * (生値 * s_scale + s_offset)` で機械 s［m］に
  換算します。IP から逆向きに測った表（QCSR）は `s_origin = 3016.315`,
  `s_direction = -1` と書けます。
- 水平全幅と垂直全幅が等しい行は**円**、違う行は**楕円**になります。形状名は寸法から
  付く（`f44_8`、`e21x27`）ので、同じ開口が何度出てきても `shape_def` は 1 つに
  まとまります。
- 同じ s に 2 行ある段差もそのまま扱えます（微小量ずらして厳密増加にします）。
  `s_direction = -1` のときは行順も反転するので、段差の上流／下流が入れ替わりません。
- CSV は `config/wall_profiles/` に置き、`file` は `config/` からの相対パスで書きます。

**(b2) コリメータの s を dispog から自動で埋める**

dispog にはコリメータの設置位置がマーカー要素として入っています（`PMD02V1` が
`D02V1`、`FPMD06H1` が `D06H1`。いずれも長さ 0 の要素）。これを読んで台帳の
`s_center` を書き込めます。

```bash
python synrad3d_wall.py ../sler_1802_60_1.dispog --update-collimators
python synrad3d_wall.py ../sler_1802_60_1.dispog --update-collimators --length 0.010 --guard 0.30
```

- 形状ライブラリに断面のあるコリメータだけを書き込み、無いものは「形状未定義」として
  一覧で報告します（次にどの断面を CAD から起こせばよいかが分かります）
- **`FPM*` は既定で除外します**。先頭の `F` は Fake の意味で、マーカーだけがあり実機は
  設置されていません。取り込みたい場合は `--include-fake` を付けます
- 先頭の `-` は反転ブロックの印なので読み飛ばします。`LPMD06V1A` のように前に別の文字が
  付くものは、コリメータ本体ではなく周辺ダクトなので拾いません

**コリメータごとの `length` / `guard`** は、台帳の `collimator_params` に書きます。

```json
"collimator_params": {
  "_default": { "length": 0.010, "guard": 0.30 },
  "D06H3":    { "guard": 0.2874 },
  "D05V1":    { "length": 0.020, "guard": 0.15 }
}
```

優先順位は次のとおりです。`collimator_params` に書いた値はコマンドラインより強いので、
`--length` / `--guard` で一括指定しても、個別に決めた台は上書きされません。

```
collimator_params[コード]  >  --length / --guard  >  台帳に既にある値
                           >  collimator_params._default  >  0.010 / 0.30
```

**(c) リッジ構造を展開する**

IP 手前の絞りのように、テーパー管の内面に山が一定ピッチで並ぶ構造は、パラメータから
展開できます。

```json
{
  "name": "IR right ridge",
  "ridge": {
    "s_start": 3015.854, "s_end": 3016.084,
    "pitch_mm": 10.0, "shape": "sawtooth", "start_with": "crest",
    "height_mm": 0.467,
    "base_d_start_mm": 20.97, "base_d_end_mm": 10.94,
    "round_mm": 0.01
  },
  "replace": true
}
```

| 項目 | 意味 |
|------|------|
| `s_start` / `s_end` | リッジ構造の始まりと終わり [m] |
| `pitch_mm` | 山のピッチ（長手方向の繰り返し間隔） |
| `height_mm` | 山の高さ（管内面から頂点まで、半径方向）。負にすると溝 |
| `crest_width_mm` | 山の頂上の長手方向の幅（`shape: "trapezoid"` のとき） |
| `flank_mm` | 山の斜面の長手方向の長さ（同上。0 なら 0.01 mm） |
| `shape` | `sawtooth` = 1 周期 2 断面の三角波 / `trapezoid` = 1 周期 4 断面の台形 |
| `start_with` | `base`（既定）/ `crest`。`s_start` を谷から始めるか山から始めるか |
| `base_d_start_mm` / `base_d_end_mm` | ベース管の内径。`s_start` → `s_end` で線形テーパー（end を省くと一定径） |
| `round_mm` | 径の丸め [mm]（既定 0.01）。同径がまとまって `shape_def` が減る |

形状名は径から付く（`f20_97`）ので、`shape_def` は自動で重複排除されます。断面は円
のみです。上の値は旧 wall file の 47 断面を最小二乗で当てはめたもので、再生成した
径は旧ファイルとの差が最大 0.08 mm・平均 0.03 mm です。

## 5. 座標系（重要）

- `-plot xy` の **原点 (0,0) は reference orbit**（ラティスの局所基準座標の x = y = 0）で、
  `r0` ではありません。`r0` は r(θ) を張る中心にすぎず、プロットには `r0` というラベル
  付きの点として別に表示されます。軸の単位は cm です。
- **reference orbit は closed orbit ではありません**。reference orbit はラティスの
  記述（bend の `g`・長さ・`ref_tilt`、`patch`、`multipole` の K0L）だけから決まる
  幾何学的な曲線で、ステアリングや四極のミスアライメントでは動きません。実際のビームが
  通る closed orbit はそこからずれ得ます（Synrad3D は起動時に
  `Closed orbit max X amplitude` を表示します）。
- **+x がリング外側**です。Bmad は `g > 0` の偏向で基準軌道を −x 方向へ曲げる
  （`ele_geometry.f90`：`r_vec = [rho*cos_one(angle), 0, rho*sin(angle)]`, `cos_one ≤ 0`）
  ので、曲率中心が −x、外側が +x になります。HER / LER とも同じ向きなので、形状
  ライブラリはリング共通で構いません。
- 偏向部では断面が曲線座標系に乗るため、**直線チェンバを偏向部に置いている箇所では
  サジッタのぶんだけモデルと実物がずれます**。またウィグラーが `wiggler` 要素ではなく
  符号交替の `sbend` 列で表現されていると reference orbit 自体が蛇行し、まっすぐな
  チェンバが蛇行した壁としてモデル化されます。ウィグラー区間の closed orbit の x が
  振動していれば前者（問題なし）、ほぼゼロなら後者（要対処）です。

## 6. CAD 断面の取り込み（`dxf_to_wall.py`）

3D CAD（Inventor 等）で断面を切って DXF に出し、それを形状ライブラリに取り込みます。

```bash
python dxf_to_wall.py f90x220A.dxf --name f90x220_Ar             # namelist を表示
python dxf_to_wall.py f90x220A.dxf --name f90x220_Ar --json      # JSON 断片を表示
python dxf_to_wall.py f90x220A.dxf --name f90x220_Ar \
       --merge config/wall_shapes.json                           # ライブラリに追記
```

対応エンティティは LINE / ARC / CIRCLE / LWPOLYLINE / POLYLINE（bulge 付き）で、
INSERT の中身も展開します。CCW への揃え直し、対称性の判定と切り詰め、頂点規則の
検査（θ 単調増加＝星形かどうか）まで行います。閉ループが複数あれば警告したうえで
最大のものを使うので、二重管のように別チェンバが混じっている DXF を黙って取り違える
ことはありません。

**dxf/ フォルダの一括取り込み**。ファイル名（拡張子を除いた部分）をそのまま断面コード
として扱うので、`dxf/f10_04.dxf` を置けば `wall_shapes.json` の `"f10_04"` になります。

```bash
python dxf_to_wall.py --dir dxf --merge config/wall_shapes.json
```

何度実行しても結果が変わらないように作ってあります。既存エントリのうち DXF 由来のもの
（`_source` が `"....dxf から変換"`）は更新し、**手で書いたエントリは上書きしません**
（`--force` で強制）。頂点規則に違反した断面は書き込まず、失敗として一覧に出します。

**DXF の bulge と Bmad の `radius_x` の対応**。bulge = tan(θ/4) で正が左回り、
Bmad の `radius_x` は CCW に辿って外へ膨らむ弧が正なので、**CCW に揃えたあとは
bulge の符号をそのまま使えます**。大きさは |R| = (弦長 / 2) / sin(2·atan(|bulge|))。

**星形でない断面（コリメータ等）**。ブレードが内側へ張り出す断面は r(θ) が一価にならず、
そのままでは Synrad3D が読めません。`--envelope` を付けると、原点から見て**最初に当たる壁**
（r(θ) の最小値）で近似した星形の多角形に置き換えます。ブレードの裏側のような、ビーム軸から
見えないポケットは埋まります。r が急変する角度は自動で二分して刻みを細かくするので、
先端のエッジは 0.004° 程度まで詰まります。

```bash
python dxf_to_wall.py D02V1.dxf --name D02V1 --envelope
```

不連続そのものは星形の多角形では表現できないため、エッジをまたぐごく狭い角度範囲
（上記なら 0.004°）では、本来ブレードの下をすり抜ける光子が近似面に当たります。

**単位**。`--scale` を省くと DXF ヘッダの `$INSUNITS` から自動判定します
（4 = mm、5 = cm、6 = m、1 = inch …）。Inventor は `$INSUNITS` を書きますが、
CST は書かない（DXF R12 形式でヘッダに `$ACADVER` しか入れない）ため、その場合は
mm と仮定して警告を出します。違う単位なら `--scale` で明示してください。
出力側で使う情報は座標と円弧だけなので、**出力元アプリによる場合分けはしていません**。

**CST から書き出すとき**。Export DXF Options の 2 つのチェックは、どちらも**外して**
ください。`Add cut lines to faces with holes` は CST MICROWAVE STUDIO 向けの穴の識別線を
足すもので（ヘルプにも他の CAD 向けには外すと明記されています）、閉ループの判定を壊します。
`Include curves` は曲線オブジェクトを一緒に書き出すもので、断面の輪郭に余計なループが
混ざります。また、書き出されるのは z = 0（WCS があれば w = 0）平面にある**すべてのソリッド**
の断面なので、真空領域のソリッドだけを対象にするか、レイヤで分けておくと確実です。

なお CST の DXF は面ごとに輪郭を書くため、面の継ぎ目で**同じ頂点が 2 回**現れます。
長さ 0 の区間は自動で除去し、除去数を報告します。

**上下非対称な断面**。D05V1 のように上下のブレード間隙が違う断面は対称展開が使えず、
全周を書き出します（`--envelope` 併用で 400 頂点弱）。Bmad の対称展開は
「全頂点 x ≥ 0 かつ y ≥ 0 → 両軸対称」「全頂点 y ≥ 0 → x 軸対称」の 2 つだけで、
**左右対称だけの断面に対する省略形はありません**。

**CAD の断面は左右が反転していることがあります。** 旧 wall file の `f90x220_Ar` は
広いアンテチェンバが +x 側ですが、`f90x220A.dxf` は −x 側です。どちらが実機の向きかは
5 章の座標系で決まるので、取り込み後に確認してください。

## 7. 運用上の注意

- 生成した wall の **s は Bmad ラティスの s と一致**している必要があります（dispog の s が
  機械 s と一致している前提）。`patch` 要素と重なる位置に断面は置けません。
- 既存の wall file を読むツールを書くときは、namelist の終端 `/` の後ろにコメントが
  付く書き方（`/ ! comment` ）に注意してください。旧 `sler_v7.wall3d` にこの形があり、
  「`/` だけの行が終端」と見なすと次のブロックまで巻き込みます。
- 旧形式の wall file（`&section_def` + `&gen_shape_def` + `"gen_shape:名前"`）は現行の
  Synrad3D が読めません（`WALL FILE IS USING AN OLD FORMAT!!` で停止）。namelist 名の
  置換と `ix_vertex_ante` の削除で変換できます。
- まず数か所を `synrad3d -plot xy` で断面確認するのが基本です。`-plot xy` は頂点
  `v(i)` にシンボルを打つので、生成した頂点をそのまま目視確認できます。縦断面は
  `-plot xs` / `-plot ys`。

## 8. 既知の制限

- **コリメータ D02V1**：旧形状（中央のブレードが y = 2.5 mm まで下がり、|x| > 7 mm では
  y = 7 mm まで開く）は r0 から見て星形でなく、r(θ) で表現できません。現在は |x| = 7 mm
  から中央へ面取りする近似を入れて `_review: true` を立ててあります。内側へ張り出す形状は
  サブチェンバでも直せない（サブチェンバは和集合なので開口を広げる方向にしか効かない）
  ため、コリメータをどこまで忠実に入れるかは要検討です。
- **IP 近傍の X 字型ビームパイプ**：両リングのパイプが衝突点で合流する形状は未対応です。
  各パイプを独立したサブチェンバとして重ねれば和集合で表現できるはずですが、2 本が互いに
  傾いているため、どちらか一方のラティス s に乗せる必要があります。
- **断面の向き**：CAD から取り込んだ断面は左右が反転していることがあります（→ 6 章）。
- **偏向部のサジッタ**：断面は曲線座標系に乗るため、直線チェンバを偏向部に置いている
  箇所ではモデルと実物がずれます（→ 5 章）。
